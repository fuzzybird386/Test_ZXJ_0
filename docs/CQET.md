# CQET 名称、灯光与关机

> 本页记录 1.1.2 的名称及灯光设计，当前 1.1.3 保留这些行为并修复 CV 超量程中断；最新镜像见 `CV_RANGE_FIX.md`。

版本：1.1.2-cqet，日期：2026-11-12。
烧录文件：`firmware/ecw54_cqet.hex`。源码均在本工程内，APP 和原固件工程未修改。

| 阶段 | 绿灯 | 红灯 | 电源保持 |
|---|---|---|---|
| 程序启动，等待手机连接 | 持续闪烁，亮 500ms、灭 500ms | 无错误时熄灭 | 开启 |
| 蓝牙连接及测量 | 常亮 | 无错误时熄灭 | 开启 |
| 蓝牙断开 | 熄灭 | 亮 250ms、灭 250ms，持续至少 3 秒 | 先保持，完成清理和提示后撤销 |
| 正常关机 | 熄灭 | 熄灭 | P0.02 拉低 |

从断线回调开始计时，提示期间停止测量、关闭电极驱动并停用蓝牙，剩余时间在命令线程等待，系统工作队列继续驱动指示灯。清理耗时超过 3 秒时不额外重复等待；若清理超时或关闭蓝牙失败，不盲目撤销电源保持，会记录 RTT 错误并保留红灯闪烁。初始化或测量错误仍可点亮红灯常亮，断线提示会覆盖该常亮状态。

首次连接前不会因等待手机而自动关机。断线后的关机流程不区分用户主动断开、手机离开或链路超时；原 APP 的自动重连不能取消该流程，需重新开机。

设备名称在主广播及扫描响应中均为 CQET。原 APP 按 AABB 服务 UUID 过滤，兼容协议仍为 AABB/AAB0/AABF/AABE，因此无需修改 APP。若手机缓存旧名称，可断开后重新扫描，在设备信息中核对固件版本。

**实际掉电条件：**启动键已松开、没有其他供电持续维持板子运行，且 LDO EN 能在 P0.02 撤销保持后降到关闭阈值。当前电路 EN 未见明确下拉，固件只能撤销保持；若红灯结束后仍有板载供电，需实测 EN 电压及漏电/外部供电，不能靠延长闪灯保证物理断电。

验证：实际 Nordic SDK 构建；真实 ARM 编译代码的模型测试覆盖 CQET 广播、APP 命令与订阅、断线不再广播、清理失败保留电源、关闭顺序，以及真实 board_io.c 的开机/连接灯态、红灯闪烁与 3 秒电源时序。没有实际手机/PCB 灯态或掉电实测。
